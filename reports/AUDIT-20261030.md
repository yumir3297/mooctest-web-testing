## 10. 报告 5：下一阶段执行建议

### 10.1 最短可行路径

**目标：以最少改动，在合法练习环境中完成一次可核验的端到端测试。**

**必须顺序完成：**

1. **P0-1 合规确认**：先确认官方是否允许 AI 辅助/自动生成脚本；未确认前不做正式提交。
2. **P0-2 环境固定**：把 Chrome 和 ChromeDriver 固定到同一主版本；`--check` 不一致时必须失败。
3. **P0-5 严格门禁**：让报告生成器拒绝阻塞/空运行/无证据用例。
4. **P0-4 新目标接入模板**：选一个合法练习站点或本地 fixture 应用，建立第二个 Page Object + 测试骨架。
5. **P0-3 提交包**：生成用例表、测试代码、截图 zip 和 manifest，做一次完整交付演练。
6. **P1-1 知识接入**：安装/合并 v0.2 规则，更新 `knowledge/README`，消除 BVA 冲突。
7. **P1-2 报告/缺陷字段**：补齐环境、前置条件、步骤、复现确认。

**可以并行：**

- P0-2 环境修复、P1-4 依赖锁定、P1-6 外部 Skill 清理。
- P1-1 知识接入与 P1-2 报告 schema 可并行。
- P2-1/P2-2 文档和上下文优化可最后做。

**验收标准（一次合法练习）：**

- 输入：一个合法练习 URL + 需求文件（不是 TodoMVC，或至少是第二个应用）。
- 产出：≥1 条正向、1 条异常、1 条边界用例；每条有预期结果和证据。
- 执行：Selenium + 显式等待；JUnit 有结果；失败有截图/源码/日志。
- 证据：manifest 0 缺失、0 哈希不一致；无未登记 MCP 文件。
- 报告：环境完整；用例级 expected/actual 正确；缺陷字段完整。
- 门禁：阻塞/空运行/坏用例必须非 0；提交包可重复生成。
- 合规：AI 使用已确认；提交格式已确认。

### 10.2 最后回答三个问题

**问题 1：我们目前距离可以真正全自动完成一次练习题，还缺什么？**

- **缺 P0-1 官方 AI 合规确认。** 现有官方资料没有说明 AI 是否允许；这是全自动流程的前提，不能用“技术上能跑”替代。
- **缺 P0-4 新目标测试生成。** 现有 `tests/` 是 TodoMVC 专用；`/web-test` smoke 固定跑 `test_add_todo`，无法直接用于新站点。

## 13. 最终一句话结论

**当前系统能做什么：** 在 TodoMVC 类已知站点上，真实完成浏览器探索、Selenium 执行、JUnit、失败取证、证据哈希和内部报告生成。

**当前系统不能做什么：** 不能对任意新赛题站点免代码修改完成闭环；不能生成官方提交包；不能确认 AI 使用合规；不能在交付前可靠阻止不合格结果。

**为什么不能：** TodoMVC 专用 Page Object/测试、知识库未接入、无严格质量门禁、无提交包、Chrome/Driver 版本漂移、官方 2026 细则和 AI 规则未核实。

**下一步先做什么：** P0-1 合规确认 → P0-2 环境固定 → P0-5 严格门禁 → P0-4 新目标接入 → P0-3 提交包；随后 P1-1 知识接入、P1-2 报告/缺陷字段。
