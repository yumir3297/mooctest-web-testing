## 0. 决策顺序（不可跳步）

`MS-00 → 方法选择 → 覆盖项定义 → 生成 → 停止判断`

### MS-00 需求分诊（前置门禁）
- **Trigger**：每次任务开始、拿到需求文本后
- **Inputs**：需求条目、赛题约束
- **Decision**：给每个需求条目打一个状态：
  - `可测`：有明确行为或可核查规则
  - `需澄清`：语义有歧义、缺少判定依据
  - `不可执行`：依赖外部系统/验证码/真实支付等
  - `非测试范围`：赛题明确排除，或超出限定角色/输入范围
- **Output**：带状态与来源编号的需求表（`requirements.json`）
- **Validation**：每条需求都有且只有一个状态；`可测` 条目必须能说出"预期从哪来"
- **Exceptions**：不得把 `需澄清` 直接改判为 `可测`；只能通过补充证据（赛题原文/需求文档）升级
- **依据**：`[ENG]`（分诊机制）+ `[MY] ch2 p.13–14`（用例必须有预期输出，无预期即不可测）

## 1. 方法选择矩阵

选择的两个正交轴：**(A) 输入域形态** 与 **(B) 业务条件是否决定同一结果**。两者都不由"参数个数"触发。

| 特征 | 方法 | 覆盖项（coverage items） | 停止条件 |
|---|---|---|---|
| 单一输入域有范围/长度/精度 | 等价类 + 边界值 | 每个分区 ≥1；每个边界按其 BVA 准则产生 2 或 3 个覆盖项 | 全部覆盖项被至少 1 条用例命中 |
| 输入有格式/枚举/校验位 | 等价类 + 边界值 + 错误猜测 | 每个合法格式类 ≥1；每类非法单独 ≥1 | 非法格式种类全覆盖 |
| 多个业务条件共同决定同一结果，且规则可枚举 | 判定表 | 每个**可达规则列** ≥1 条用例 | 全部可达列命中；不可达列已标注原因 |
| 存在状态机（登录态、订单/运单、审批、提交） | 状态迁移 | 每条合法迁移 ≥1；每个关键非法迁移 ≥1 | 迁移全覆盖，且含重复触发/回退 |
| 参数相互独立、需求未给出组合约束、但实际存在交互风险 | 组合覆盖（pairwise 起） | 每个参数对的取值组合 ≥1 | 覆盖强度达成（默认 2-way）；高风险参数对单独全组合 |
| 需求缺失/自相矛盾/页面行为与需求冲突 | 微型 charter 探索 | charter 问题清单 | charter 内问题答完或连续无新发现 |
| 阈值型非功能需求 | 独立非功能用例集 | 每条有数值型判据 | 有阈值即可断言；无阈值转 `需澄清` |

## 2. 规则明细

### MS-01 分区与边界（v0.2 修正）
- **Source**：`[MY] ch4 p.51–57`（分区、输入与输出边界）；`[ISTQB] §4.2.2`（2-value / 3-value BVA 的覆盖项定义）
- **Trigger**：存在有量纲、有精度、有上下限的输入或输出
- **Preconditions**：分区已确定；边界来源可指认（需求或业务规则）
- **Inputs**：字段、单位、精度/步进、上下限、开闭区间语义
- **Decision**：
  1. 先分区（有效/无效），**再**定边界；边界必须落在分区交界处。
  2. 对每个边界选择 BVA 准则：
     - **2-value**：覆盖项 = {边界值, 相邻分区最邻近值}（2 项）。默认用于低风险、连续大整数域。
     - **3-value**：覆盖项 = {边界值, 两侧最邻近值}（3 项）。用于高风险（金额、计数上限、临界判定），或怀疑实现把 `≤` 写成 `<`/`=` 时。
  3. 邻近值取"**页面上真实可表示**的最邻近值"（受步进/精度/单位限制）。若无可表示邻近值（纯枚举、单选、无精度概念），该覆盖项记 `N/A` 并写明原因。
     - **精度必须与字段一致**：整数字段的邻近值是整数（如 [1,20] 的邻近值为 0 与 21），**不得**改用小数；精度 0.1 的字段才用 0.1 步进取值。
  4. **开闭区间**：闭边界（含端点）的覆盖项 = 端点 + 两侧最邻近可表示值；开边界（不含端点）时端点本身属无效分区，其覆盖项 = 端点 + 有效侧最邻近可表示值。开闭语义未写明时转 `需澄清`，不擅自选一种。
  5. 输出边界（如金额合计、条数、分页总数）同样作为覆盖项来源。
- **Output**：边界覆盖项表（边界 / 分区对 / 准则 / 覆盖项值 / 取值依据）
- **Validation**：每个覆盖项都能回答"为什么是它"；无凭空写出的 min-1 / max+1
- **Exceptions**：
  - 赛题给出固定样例值时，只覆盖给定值 + 其可表示邻近值，不越界造数；
  - 单位未知（g 还是 kg）时先转 `需澄清`，不得自行假定；
  - **不得**把"每边界 4 点"当成通用门禁。
- **V0.1 弃用说明**：v0.1 的"每边界 min-1/min/max/max+1 四点"规则作废，`REV-02` 相应改为按覆盖项计数。
- **Example**：重量 0.1–30 kg，步进 0.1，高风险（计费）→ 下边界 0.1 用 3-value = {0.0, 0.1, 0.2}；上边界 30 用 3-value = {29.9, 30.0, 30.1}。合计 6 个覆盖项，而非 8 个机械点。

### MS-02 格式与枚举
- **Source**：`[MY] ch4 p.51–52`；错误猜测高发情形 `[MY] ch4 p.81`
- **Trigger**：正则、校验位、编码规则、多合法格式并存
- **Decision**：枚举合法格式种类 → 每类非法方式单列（空、超长、字符集错、校验位错、前后空格、全角/半角）→ 每种非法单独一条用例
- **Output**：合法/非法样例矩阵
- **Validation**：非法种类数 = 需求可推导种类数；不得只测"乱输一串"
- **Exceptions**：多规则叠加（长度+字符集+校验位）先做单规则隔离，再补叠加

### MS-03 判定表（v0.2 修正触发条件）
- **Source**：`[MY] ch4 p.61–66`（建模）、`p.72–74`（防爆炸回溯）、`p.79`（暴露规格歧义）、`p.80`（边界值代入列）
- **Trigger**：**多个业务条件共同决定同一结果，且条件-结果能枚举成规则**。
  - ❌ 不再由"参数 ≥4"或"条件数 ≤4"触发。
  - 参数多但相互独立、无业务规则约束 → 属组合覆盖问题，走 `MS-05`。
- **Preconditions**：条件与动作可从需求逐条标出；约束（互斥/依赖）已知
- **Decision**：
  1. 标 cause / effect；
  2. 加约束（E 至多一 / I 至少一 / O 有且仅一 / R 依赖 / M 屏蔽）；
  3. 回溯生成列，or 节点只置一个输入为 1；
  4. 每列一条用例；不可达列显式标注；
  5. 把 `MS-01` 的边界值**代入已有列**，不新增列。
- **Output**：条件-动作表 + 用例列
- **Validation**：每条可达规则 ≥1 列；不可达列有原因；边界值已代入而非另起用例
- **Exceptions**：条件数 >6 时，先合并同动作规则、剔除不可达，仍不可控则改为"关键规则单列 + 组合覆盖"
- **Example**：会员/券/保价三条件决定应付金额 → 8 列，其中 2 列不可达；边界值（满 100 临界）代入对应列。

### MS-04 状态迁移
- **Source**：`[ISTQB] §4.2.4`；`[EI] ch8 p.88–99`（识别状态与事件、转 state table）
- **Trigger**：≥3 个状态，含不可逆或高风险操作
- **Decision**：建状态-事件矩阵 → 每条合法迁移 1 例 → 关键非法迁移各 1 例 → 追加"重复触发""中途回退"
- **Output**：状态矩阵 + 迁移用例
- **Validation**：无孤立状态、无出口状态、非法迁移已覆盖
- **Exceptions**：状态由定时任务驱动时，注明时间可控性；不可控则标 `不可执行`

### MS-05 组合覆盖（v0.2 修正来源）
- **Source**：`[NIST] SP 800-142`（组合测试的公开方法学出处）；组合爆炸问题见 `[MY] ch4 p.61`
- **Trigger**：**同时满足**——参数相互独立、需求未给出必须穷举的约束、实际存在交互风险、有合法取值约束与时间预算
- **Preconditions**：参数取值集合已枚举；非法组合已标注
- **Decision**：
  0. **先判定是否真的需要组合覆盖**：若需求明确声明字段之间没有组合业务规则、且各字段相互独立（如"两个必填 + 两个可选"的普通查询表单），则**不做**组合覆盖，只做逐字段分区与必填/可选的单因素用例。
  1. 先剔除非法组合（约束过滤）；
  2. 默认 2-way（pairwise）覆盖；
  3. 高风险参数对（金额 × 权限 × 状态）单独做全组合；
  4. 题目指定组合优先，不得用算法结果覆盖题目要求。
- **Output**：覆盖数组（covering array）+ 高风险全组合子表；若第 0 步判定不需要，输出"不适用"及理由
- **Validation**：任一参数对的取值组合至少出现一次；未启用时理由可复核
- **Exceptions**：参数之间其实由业务规则约束 → 回到 `MS-03`，不要用 pairwise 代替判定表
- **Example**：城市 × 重量段 × 时效产品 × 保价 → pairwise 9 行；保价 × 重量段全组合 6 行。反例：寄件城市/收件城市/备注/参考编号无交互规则 → 不适用组合覆盖。

### MS-06 微型 charter 探索
- **Source**：`[EI] ch2 p.29–32`（charter 模板与好坏标准）、`ch13 p.152`（结束判据）
- **Trigger**：需求缺失、页面行为与需求冲突、高风险点待确认
- **Preconditions**：已确认无法通过需求澄清解决
- **Decision**：写 4 字段微 charter——目标 / 范围 / 停止条件 / 可转化产物；限时；按 `defect_discovery` 清单探索；只记录真实观察
- **Output**：`observations.json`（观察项）+ 可固化的不变量/用例候选
- **Validation**：charter 不过细（退化成用例）也不过宽（无法判断结束）；观察项未被写成"需求"
- **Exceptions**：**不建立**与正式用例集并行的探索工作流；探索结果须经 `ORA-01/02` 证据化后才进入正式用例
- **Example**："探索订单列表在筛选与回退组合下是否出现数据错位，30 分钟，产出 1 条可检验不变量"

### MS-07 非功能需求
- **Source**：`[MY] ch10 p.206`（无量化规格无法判断性能是否达标）
- **Decision**：有阈值 → 数值型判据；无阈值 → `需澄清`，不得自定通过标准；与功能用例分开统计
- **Validation**：每条非功能用例都有数字型预期或已转澄清

### MS-08 组合顺序（主流程）
- **Source**：`[MY] ch4 p.82–83`
- **Decision**：① 有业务条件组合 → 先判定表；② 无论如何做分区与边界；③ 补无效类；④ 错误猜测追加；⑤ 有代码时用覆盖准则查漏
- **Validation**：四层（规则/边界/异常/经验）都有产出；不出现"只有正向用例"

### MS-09 停止条件（v0.2 改为覆盖项口径）
- **Source**：`[MY] ch4 p.83`；`[EI] ch13 p.152`；`[ISTQB] §4.2.2`
- **Trigger**：准备结束某功能点设计
- **Decision**：以下**全部**满足才停：
  1. 每个 `可测` 需求 ≥1 条**有判据**的正式用例；
  2. 每个无效分区 ≥1 条独立用例；
  3. 每个边界覆盖项（2 或 3 项，按 `MS-01` 选定准则）均被命中；
  4. 每条可达判定规则列 ≥1 条；
  5. 每条合法状态迁移 ≥1、关键非法迁移 ≥1；
  6. 无 `ORACLE-UNKNOWN` 用例混入正式用例集；
  7. 缺口已写入 `coverage_report.json`。
- **Output**：可提交用例集 + 缺口清单
- **Validation**：按覆盖项逐条核对，不以"用例数"作为达成标志
- **Exceptions**：题目限定用例数时按 `MS-10` 取舍

### MS-10 赛题约束优先
- **Source**：`[ENG]` + `[S-01]` 交付物约束
- **Decision**：赛题明示的输入范围、角色、样例值、用例上限、文件命名、工具限制 **一律优先**；越界想法只写备注，不生成正式用例；超限时按 风险 > 覆盖唯一性 > 可自动化性 排序删减
- **Validation**：逐条核对数据是否越界；总数 ≤ 上限
- **Exceptions**：赛题约束与业务常识冲突时，以赛题为准并备注

## 3. 组合、重复与冲突

### 3.1 推荐叠加
| 组合 | 方式 | 收益 |
|---|---|---|
| 分区 + 边界 | 先分区，边界取分区交界 | 一张表同时表达类与界 |
| 判定表 + 边界 | 边界值代入已有列 | `[MY] ch4 p.80`：23 个边界条件并入 37 条用例而不新增用例 |
| 状态迁移 + 错误猜测 | 每条迁移追加重复触发/中断 | 覆盖幂等问题 |
| charter + 缺陷清单 | charter 定向，清单保证维度 | 降低探索随机性 |

### 3.2 重复与冲突
| 冲突对 | 表现 | 处置 |
|---|---|---|
| 分区代表值 vs 边界值 | 同一分区出两条近似用例 | 边界值优先；分区只保留"类归属"信息 |
| 判定表 vs 组合覆盖 | 同一组合被算两次 | 有业务规则的归判定表；pairwise 只处理独立参数 |
| 状态迁移 vs 端到端场景 | 同一主流程两条 | 主流程归状态迁移；场景法只做跨模块串联 |
| 错误猜测 vs 无效分区 | "空值/0"各写一条 | 归无效分区；错误猜测只补分区外经验项 |

### 3.3 爆炸控制
| 方法 | 爆炸源 | 控制 |
|---|---|---|
| 判定表 | 条件数指数增长 | 条件 >6 拆分规格；or 节点只置一个为 1 |
| 多条件覆盖 | 2^n | 剔除不可达组合；降级为判定/条件覆盖 |
| 边界值 | 字段 × 输出 × 覆盖项 | 只对高风险字段用 3-value；其余 2-value |
| 组合覆盖 | 参数数 × 取值数 | 约束过滤 + 2-way；仅高风险对全组合 |

### 3.4 Web 赛道默认优先级（推断，非当届规则）
1 主流程正向（覆盖率主体）→ 2 表单分区与边界 → 3 业务条件判定表 → 4 状态迁移 → 5 错误猜测补充 → 6 有条件探索。
依据 `[S-01]`：评分含"功能点覆盖 + 等价类/边界值/组合测试方法 + 脚本与用例一致性"。2026 细则未发布，故为推断。
