## 0. 全局判定顺序（每次设计用例前必走）

1. **先定测试依据**：需求/验收标准/页面原型，缺一项就登记为假设，不得凭空补齐业务规则。
2. **再定风险**：按「用户可见 + 不可逆 + 数据/资金 + 高频」四个维度给功能打分，高风险功能必须覆盖正向、异常、边界、状态异常四类。
3. **再选方法**：按 §1 的输入特征匹配方法，不允许多方法无差别铺开。
4. **最后定停止条件**：满足 §5 的出口准则即停止，不追求用例数量堆砌。

依据：ISTQB CTFL v4.0.1 风险驱动测试与测试依据/可追溯性章节 `[S-02]`；2025 Web 赛项评分对「用例充分性」的要求 `[S-01]`。

## 1. 方法选择决策表

> ⚠ **本表已被 `MS-01..MS-05` 取代（2026-10-31）**；首行的"每边界四点"已作废。见文件顶部横幅。

| 输入特征 | 选用方法 | 输出形态 | 停止条件 |
|---|---|---|---|
| 单一输入字段有取值范围 / 长度 / 类型 / 枚举 | 等价类划分 + 边界值分析 | 输入域切分表 + 边界点清单 | 每个有效类 ≥1 例，每类无效输入 ≥1 例，每个边界取 min-1/min/max/max+1 |
| 输入有格式/正则/枚举约束（手机号、金额、日期） | 等价类 + 边界值 + 错误推测 | 合法/非法样例矩阵 | 覆盖全部非法格式种类，不只测一个错例 |
| 多个条件组合决定同一结果（如优惠、权限、状态联动） | 决策表 | 条件-动作表 | 每条规则 ≥1 例；不可达规则单独标注 |
| 业务有明确状态机（订单、审批、登录态） | 状态迁移测试 | 状态-事件矩阵 | 每条合法迁移 ≥1 例；每个关键非法迁移 ≥1 例 |
| 多参数、全组合爆炸不可行 | 组合测试（成对/正交） | 参数-取值对表 | 两两覆盖达成即停；高风险参数对追加全组合 |
| 无明确规格、探索性场景、页面交互不确定 | 探索式测试（会话式，限时） | 探索记录 + 缺陷清单 | 时间盒结束或连续无新发现 |
| 性能/并发/安全类需求 | 单独列为非功能用例集 | 非功能用例 | 按需求阈值给出可量化预期；无阈值则登记为待确认 |

依据：ISTQB CTFL v4.0.1 §4.2.1–4.2.4（等价类、边界值、决策表、状态迁移）`[S-02]`；ISO/IEC/IEEE 29119-4 公开摘要中的测试技术分类 `[S-03]`。

### 1.1 决策表适用性快筛
- 条件数 ≤ 4 → 可用完整决策表。
- 条件数 5–6 → 只保留可达规则，合并同动作规则。
- 条件数 > 6 → 改用组合测试 + 关键规则单列。

### 1.2 状态迁移适用性快筛
- 有 3 个以上状态且存在「不可逆操作」→ 必做。
- 迁移路径含支付/提交/删除 → 每条路径必须包含「重复提交」「返回上一步」两个异常例。

## 2. 用例粒度与写法规则

1. **一条用例一个可判定目标**：预期结果必须是可观测的（页面元素、文案、URL、数据变化、提示语），禁止「显示正常」「功能可用」这类不可判定表述。
2. **步骤必须可被自动化复现**：每一步都能映射到一次浏览器动作或一次数据准备，不写「进入相关页面」这种模糊动作。
3. **前置条件显式化**：登录态、账号角色、数据初始状态三选一必须写明，缺项登记为假设。
4. **数据与步骤分离**：用例表用数据占位符（`${用户名}`），便于参数化与批量数据驱动。
5. **优先级依据风险**：P0 = 阻断主流程/资金/不可逆；P1 = 主流程分支；P2 = 提示与边界；P3 = 兼容与体验。

依据：2025 Web 赛项评分对「用例可读性、可复现性、代码-用例一致性」的要求 `[S-01]`；ISTQB 测试条件与测试用例的区别 `[S-02]`。

## 3. 需求 → 用例的可追溯规则

- 每个需求点分配唯一 `REQ-xx`；每条用例必须回指至少一个 `REQ-xx`。
- 同一需求点被 ≥3 条用例覆盖时，标注为「高风险覆盖」，便于评审快速定位。
- 需求点无对应用例 → 必须在缺口清单中显式列出，不允许静默遗漏。
- 用例无对应需求 → 标注来源为「探索发现」并说明依据（页面实际行为/常识约束）。

依据：ISTQB 测试依据与测试件之间的可追溯性 `[S-02]`；ISO/IEC/IEEE 29119-3 公开摘要中的可追溯要求 `[S-03]`。

---

## 4. 冲突与优先级仲裁

当多种方法给出相互矛盾的用例集时，按以下顺序仲裁：

1. **赛事评分维度**（充分性 > 可复现性 > 可读性）`[S-01]`
2. **风险等级**（高风险功能的方法优先）
3. **可自动化程度**（能稳定断言的优先，纯人工判断的降级为备注）
4. **执行成本**（同等价值取步骤更少的）

## 5. 出口准则（停止设计用例的条件）

> ⚠ **本节已被 `MS-09` + `REV-02` 取代（2026-10-31）**：停止条件按覆盖项达成，不按 min-1/min/max/max+1 四点。

同时满足才停：

- 每个 `REQ-xx` 至少 1 条正向用例；
- 每个输入域每个无效等价类 ≥1 条异常用例；
- 每个边界点（min-1 / min / max / max+1）≥1 条用例；
- 每条合法状态迁移 ≥1 条用例，关键非法迁移 ≥1 条；
- 主流程全部 P0 用例可被 Selenium 脚本稳定执行；
- 未覆盖项已写入缺口清单并说明原因。

依据：ISTQB 测试设计与覆盖准则 `[S-02]`；2025 评分准则中的用例充分性要求 `[S-01]`。

## 6. 明确不做的事

- 不对未在需求中出现的状态码、金额规则、并发数值做「猜测式」设计，只能登记为假设。
- 不复制教材/标准原文段落作为用例依据，引用时只写方法与结论。
- 不用 2025 评分表反推 2026 赛题的具体分值分布。
