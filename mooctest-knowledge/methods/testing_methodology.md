# 测试设计方法论（结构化总结）

> 目的：给 AI Agent 提供"方法是什么、能产出什么、边界在哪"的事实底座。
> 本文件不含"何时选哪个"——选法见 `decision-rules/method_selector.md`；预期结果判定见 `decision-rules/test_oracle.md`。
> 所有结论只保留"方法名 + 机制 + 产出形态"，不复制教材原文。

---

## 0. 总纲：为什么必须做方法选择

- 穷举输入不可行、穷举路径更不可行；测试的经济学目标是用有限用例最大化检错收益。[Myers ch2 p.9–10；ch4 p.41]
- 因此测试设计的核心命题不是"设计多少用例"，而是**"在所有可能用例中选哪个子集最可能发现最多缺陷"**。[Myers ch4 p.41]
- 随机输入测试是效率最低的方法；本知识库禁止把"随机/随手点几下"当成测试设计。[Myers ch4 p.41]

## 1. 黑盒方法（基于规格，不看代码）

### 1.1 等价类划分（Equivalence Partitioning）

| 项 | 内容 |
|---|---|
| 机制 | 把输入域切成若干类，假设类内任一代表值的检错效果等价 |
| 判定依据 | 一条用例应"减少后续需设计的用例数"，且"覆盖同类其他输入"[Myers ch4 p.49–50] |
| 产出 | 有效类表 + 无效类表 + 代表值 |
| 关键规则 | 范围/个数/枚举/必须满足 四类输入条件各有固定的切分方式[Myers ch4 p.51–52] |
| 用例组织 | 有效类尽量合并进同一用例；**每个无效类单独一条用例**，防止错误检查互相遮蔽[Myers ch4 p.52] |
| 强度 | 高于随机；仍会漏掉边界与组合[Myers ch4 p.55] |

教材示例规模参考：一个 Fortran DIMENSION 语句的规格，切出 43 个等价类、17 条用例（其中 1 条覆盖 10 个有效类）。[Myers ch4 p.51–55]

### 1.2 边界值分析（Boundary Value Analysis）

| 项 | 内容 |
|---|---|
| 机制 | 在等价类边缘取点，并同时看**输入边界与输出边界** |
| 与 EP 的两点差异 | ① 不只取代表值，而是取边界；② 不只测输入空间，也从输出等价类取值[Myers ch4 p.55] |
| 教材取值指引 | 范围取端点及其越界侧；个数取界值及相邻值；每条输出条件同样取端点；有序集合取首尾；其余靠创造力补充[Myers ch4 p.56] |
| 高价值原因 | 编码常见错误是边界比较符写错（`>=` 误写为 `>`），只有边界点能暴露[Myers ch4 p.57] |
| **覆盖项口径（v0.2）** | 边界覆盖项按所选准则确定：**2-value** = {边界值, 相邻分区最邻近值}；**3-value** = {边界值, 两侧最邻近值}。选择依据为风险与精度，见 [ISTQB §4.2.2]；ISTQB 明确 3-value 可发现 2-value 漏掉的 `≤` 误实现为 `=` 的缺陷 |
| 产出 | 边界覆盖项表（边界 / 分区对 / 准则 / 覆盖项值 / 取值依据），而**不是**固定的"每边界四点" |
| 常见误用 | 只测输入、不测输出；把"体验上的边缘"当成数值边界[Myers ch4 p.56, p.60]；无视页面精度与可输入性凭空造邻近值 |

教材示例规模参考：一个阅卷程序规格共导出 42 条边界用例，其中相当部分来自输出边界（并列名次、标准差为 0、报告刚好占满一页）。[Myers ch4 p.57–61]

### 1.3 因果图 → 判定表（Cause-Effect Graphing）

| 项 | 内容 |
|---|---|
| 解决的问题 | EP 与 BVA 都不探索"输入条件组合"[Myers ch4 p.61] |
| 六步流程 | 切分规格 → 标出 cause/effect → 连布尔图 → 加约束 → 转有限项判定表 → 每列转一条用例[Myers ch4 p.62] |
| 约束类型 | E（至多一个）、I（至少一个）、O（有且仅有一个）、R（requires）、M（mask）[Myers ch4 p.65] |
| 防爆炸要点 | 回溯 or 节点只置一个输入为 1（path sensitizing）；and 输出为 0 时同构情形只枚举一次[Myers ch4 p.73–74] |
| 附带收益 | 能暴露规格的歧义与不完整（教材示例因"每行固定 4 个 word"与内存尾端冲突而发现规格缺陷）[Myers ch4 p.79] |
| 产出 | 条件-动作表（判定表），每列一条用例，列内同时给出"哪些 effect 应出现、哪些应不出现" |
| 边界短板 | 因果图本身不充分探索边界；应另做 BVA，然后把边界值**代入已有列**而非另加用例[Myers ch4 p.79–80] |

### 1.4 错误猜测（Error Guessing）

| 项 | 内容 |
|---|---|
| 机制 | 依据经验枚举"易错情形"，再为每条写用例；无固定算法[Myers ch4 p.80–81] |
| 教材给出的高发情形 | 输入出现 0；输出被强制为 0；集合的"空"与"仅一个"；排序类：空表/单元素/全相同/已有序[Myers ch4 p.81] |
| 规格视角 | 找出**写规格的人默认省略、但开发者可能做了假设**的地方[Myers ch4 p.81] |
| 定位 | 补充手段，不替代 EP/BVA/决策表；只能在前四类方法之后追加[Myers ch4 p.83] |

## 2. 白盒 / 覆盖准则

> 说明：本轮材料范围为 Myers 与《Explore It!》。覆盖准则以 Myers ch4 的定义为主，并用 ISTQB CTFL v4.0.1 §4.3 交叉核对；不引用其他教材。

| 准则 | 要求 | 强度 / 已知弱点 | 出处 |
|---|---|---|---|
| 语句覆盖 | 每条可执行语句至少执行一次 | 最弱；无法发现 `and` 应为 `or`、比较符写错、某些路径未走 | Myers ch4 p.43–44；ISTQB §4.3.1 |
| 判定（分支）覆盖 | 每个判定至少取真、假各一次 | 不能保证每个**条件**取到两种结果 | Myers ch4 p.44；ISTQB §4.3.2 |
| 条件覆盖 | 每个判定内的每个条件至少取真、假各一次 | 可能覆盖了全部条件结果却没覆盖判定结果 | Myers ch4 p.45–46 |
| 判定/条件覆盖 | 条件结果 + 判定结果都覆盖 | 短路求值会遮蔽后续条件 | Myers ch4 p.46–47 |
| 多条件覆盖 | 每个判定内条件结果的所有**可能**组合都覆盖 | 最强；组合可能爆炸，需剔除不可达组合 | Myers ch4 p.47–49 |

- 分支覆盖蕴含语句覆盖，反之不成立。[ISTQB §4.3.2]
- Web 赛道通常拿不到被测应用源码，**白盒准则只用于"自检逻辑是否漏分支"的思维工具，不作为覆盖率交付指标**（交付物是功能用例 + Selenium 脚本，见 S-01）。

## 3. 状态迁移测试

| 项 | 内容 |
|---|---|
| 适用形态 | 有明确状态机：登录态、订单/运单流转、审核流、支付流 |
| 产出 | 状态-事件矩阵（state table）或状态图 |
| 覆盖要求 | 每条合法迁移至少 1 例；关键非法迁移至少 1 例（ISTQB §4.2.4 的状态迁移测试框架） |
| 探索补充 | 状态可以从"行为变化、时间触发、用户动作、系统事件"反推；把状态图转成表可暴露异常迁移；要专门尝试"中断状态""重复触发同一事件"[ExploreIt ch8 p.88–99] |
| Web 特化 | 浏览器回退/前进会重放事件，可能导致重复提交（见 `defect_discovery.md` DEF-07）[ExploreIt A2 p.166] |

## 4. 组合测试

| 项 | 内容 |
|---|---|
| 问题 | 多参数全组合数量天文级，任意挑子集会失去系统性[Myers ch4 p.61] |
| 教材口径 | Myers 未给出成对/正交覆盖的完整算法；他给出的"系统化组合"手段就是因果图 → 判定表[Myers ch4 p.61–62] |
| 成对（pairwise） | 出处改为 **NIST SP 800-142（Practical Combinatorial Testing）**，属有正式公开文献支持的工程实践；**不声称** Myers 或 Explore It! 提供了该方法 |
| 使用前提（v0.2） | ① 参数相互独立；② 需求未要求穷举；③ 实际存在交互风险；④ 有合法约束过滤与时间预算。**不以参数个数作为触发条件** |
| 使用边界 | 高风险参数对必须单独做全组合；成对覆盖不能替代业务规则判定表 |

## 5. 探索式测试

| 项 | 内容 |
|---|---|
| 定义 | 同时进行"学习、设计、执行"，以**时间盒会话 + charter**为单位，不是随机点击 |
| 结构 | Charter（Target / Resources / Information）+ 时间盒 + 记录 + 汇报[ExploreIt ch2 p.29] |
| 好 charter 的标准 | 给方向、不指定具体动作；过细就退化成测试用例；过宽则无法判断何时结束[ExploreIt ch2 p.31–32] |
| 结束判据 | 开放问题答完 / 不再学到新东西 / 更多信息不改变决策 / 其他信息更有价值[ExploreIt ch13 p.152] |
| 与脚本化测试关系 | 两者互补：charter 产出"值得固化的场景"，再转成脚本化用例；不是替代关系（`[工程经验]`，与 ExploreIt ch13 的整合思路一致） |

## 6. 方法的能力边界（供决策表引用）

| 方法 | 能发现 | 发现不了 |
|---|---|---|
| EP | 类间行为差异、类型/枚举非法值 | 边界错误、组合冲突 |
| BVA | 边界比较符、计数临界 | 条件组合、顺序依赖 |
| 决策表/因果图 | 条件组合、规则缺失、规格歧义 | 数值边界精细差异、时序问题 |
| 状态迁移 | 非法迁移、重复触发、状态残留 | 单字段边界、纯展示问题 |
| 错误猜测 | 经验型高发缺陷 | 系统性遗漏（本身不系统） |
| 探索式 | 未知风险、交互副作用、不可预演问题 | 可重复的量化覆盖证明 |

> 这张表是 `method_selector.md` 中"组合与冲突"分析的直接依据。
